## 1. Methodology

**Extraction.** A throwaway Python parser (kept in `/tmp/recon/`, never written into the repo) walked every
`*.py` file in the repo root plus `services/`, `backend/`, `models/` and `pulse_communications_v2/`. For each
line matching `@<object>.(route|get|post|put|patch|delete)(` it:

* joined multi-line decorator expressions until parentheses balanced;
* pulled the first string literal as the rule, resolving f-string interpolations such as `f"{API_PREFIX}/connect"`
  and bare `route(API_PREFIX)` against module-level string constants;
* read `methods=[...]` when present, otherwise inferred the verb from the shorthand decorator
  (`.get` -> GET, `.post` -> POST, ...), defaulting to GET for a bare `.route()`;
* walked forward past any intervening decorators to the `def` line to capture the handler name;
* captured the handler body (indentation-delimited) and grepped it for the codebase's auth helpers and for
  `services.*` imports/usages, to fill the AUTH and RELATED SERVICE MODULE columns.

Blueprint `url_prefix` was applied where declared (only `services/sentinel/api.py` uses one:
`/api/admin/sentinel`). The 36 Business OS commerce endpoints registered via `add_url_rule` from
`services/business_os/commerce_gateway.ROUTES` were transcribed from that table by hand and merged in.

Note the difference between *decorators* and *distinct URLs*: many handlers carry several `.route()` decorators
(e.g. `stripe_webhook` is mounted at five paths). 2,007 is the count of `(path, methods)` registrations.

**What this does NOT cover.**

* Optional route packs are mounted inside `try/except` blocks (`_load_route_pack(...)` in `bot.py`), so a
  subsystem listed here can be absent at runtime if its import fails or its feature flag is off. Every
  Business OS controller returns 404 when its `BUSINESS_OS_*` flag is off. This map is the *static* surface.
* Request/response body schemas, query parameters and status codes are not enumerated — handlers build JSON
  inline and there is no OpenAPI/spec artefact anywhere in the repo.
* `services/command_center_worker/app.py` is a **separate Flask app** (an internal sidecar), not mounted on
  `bot:app`. Its 26 `/internal/command-center/*` routes are listed but are not part of the public surface.
* AUTH is inferred from the first auth helper found in the handler body. Handlers that branch (public read /
  authenticated write in one function) are shown with the stronger classification; a handful of
  `public/none` rows are actually guarded by a feature flag or by an inner helper this heuristic missed.
* Purposes are derived mechanically from handler names except where noted in the per-area commentary.

## 3. Routes by product area

### Feed / Posts / Media — 71 routes

The core social graph surface. `/api/pulse/posts` is the CRUD spine: `POST /api/pulse/posts` creates,
`GET|PATCH|DELETE /api/pulse/posts/<id>` reads/edits/removes, and the per-post verbs (`/react`, `/view`, `/save`,
`/pin`, `/hide`, `/repost`, `/comments`) each have their own endpoint rather than a generic action route.
`GET /api/pulse/feed` is the ranked timeline; `/pulse`, `/pulse/trending`, `/pulse/following`, `/pulse/questions`
and `/pulse/my-posts` all render through the same `pulse_page` view with a tab argument. Six legacy home paths
(`/home`, `/feed`, `/pulse/home`, `/pulse/legacy-home`, `/pulse/home-legacy`, `/pulse/old-home`, `/pulse/legacy`)
funnel into `legacy_pulsesoc_home_redirect`. Media has two upload paths: a simple `POST /api/pulse/media/upload`
and a resumable multipart session (`/api/pulse/media/uploads` -> `/parts/sign` -> `/complete` -> `/finalize`,
with `/abort` and `/refresh`), plus a Mux direct-upload lane for video. `/api/pulse/music/*` is a licensed audio
catalogue used for attaching sound to posts, reels and status.

### Messaging / Chat — 149 routes

The largest and most duplicated area. There are **three generations** of messaging API live at once:
(1) legacy `/api/messages/*` and `/api/chat/*` in `bot.py`; (2) `/api/pulse/messages/*` (the current app API,
also in `bot.py`); and (3) **Communications 2.0** in `pulse_communications_v2/routes.py`, mounted at
`/api/pulse/communications/v2/*` with a shorter alias `/api/pulse/comm/v2/*` for a subset. V2 is the richest:
conversation control center, pins/links/media/export, moderation, AI summary and smart-replies, archive/mute/
unread, forward/edit/delete, attachments, blocks, communities and channels. Realtime is served two ways:
`GET .../realtime` (polling) and `GET .../realtime/stream` (SSE) — the SSE route is gated by
`_main_app_sse_allowed()` and falls back to polling to keep long-lived connections off the web workers.
`/api/chat-room` and `/api/pulse/chatrooms` and `/api/pulse/messages/rooms` are three aliases of the same
chatroom handlers.

### Calls (voice/video) — 23 routes

LiveKit-backed 1:1 and group calls. `POST /api/calls/start` mints a call, `POST /api/calls/<id>/join-token`
returns the LiveKit access token, and `GET /api/calls/<id>/events` is the signalling/event poll. The remaining
endpoints are per-call device state that the server owns rather than the client: mute/unmute audio, enable/disable
video, speaker, switch-camera, screen-share start/stop, minimize/restore, visibility, quality. That server-side
ownership is the arbitration layer referenced by `docs/realtime_audio_change_policy.md` — clients report state,
they do not unilaterally reconfigure the audio session. Calls can also be started from a conversation via
`POST /api/pulse/communications/v2/conversations/<ref>/{voice,video}/start` (both bind to `start_conversation_call`).

### UNDX — 35 routes

Three separate surfaces. (1) `/api/undx/*` on the main app — `chat`, `agent-council`, and the execution

`APPROVE UNDX WRITE` (and a second guard phrase when the batch touches UNDX's own constraint files).

`UNDX_DESKTOP_CONNECTOR_URL` (default `http://127.0.0.1:8765`). (3) `undx_desktop_connector.py` is a **separate
localhost-only Flask app** (binds `127.0.0.1:8765`) exposing `/workspace/register`, `/repo/scan`, `/file/read`,
`/proposal/generate`, `/patch/apply`, `/validate/run`, `/git/{status,commit,push}` and `/health`. It has **no
bearer/token auth** — its trust boundary is the loopback bind plus a CORS origin allowlist. Anything that can
reach that port can drive it. (4) `/api/business-os/undx/*` is the governed agent layer: tools registry,
permissions, policies, requests, confirmations, receipts, decisions, action-center, `evaluate`, and

## 4. Auth patterns

There are **no auth decorators on `bot.py` routes**. Out of 1,713 route decorators in `bot.py`, zero carry a
`@login_required`-style wrapper. Authentication is a *call-and-check* convention inside each handler body:

```python
@webhook_app.route("/api/pulse/welcome-state", methods=["GET"])
def api_pulse_welcome_state():
    init_db()
    user = api_account_user()
    if not user:
        return api_error("Login required.", 401)
```

Forget the `if not user:` line and the route silently becomes public. That is the single biggest structural
auth risk in this codebase. The only true decorator in the repo is `@require_internal_auth` in
`services/command_center_worker/` (25 uses), and the only blueprint-level gate is
`@sentinel_bp.before_request` in `services/sentinel/api.py`.

### 4.5 Caveats on the `public/none` bucket

Three sources of false "public" classification, all verified:

1. **Covered by a `before_request` gate.** All 120 `/api/arena/*` routes and all `/api/business-os/*` routes are
   authenticated by hooks, not by handler code. The 18 Sentinel routes are gated by a blueprint
   `before_request` (corrected in the tables above to `admin-session`).
2. **Split-behaviour handlers.** Endpoints that serve a public read and an authenticated write in one function
   (e.g. `GET|POST /api/pulse/posts/<id>/comments`) resolve the user lazily and may not match the heuristic.
3. **Debug endpoints.** `/debug/email-test`, `/debug/stripe-user`, `/debug/user-email-status`,
   `/debug/password-reset-email-test`, `/debug/upgrade-email-test` show no auth helper in-handler. These
   warrant a manual read before any production claim is made about them — flagged, not concluded.

### 4.6 Session and token facts worth carrying forward

* Session cookie is `SameSite=Lax` (the CSRF comment at `bot.py:2977` treats this as a mitigation, not a control).
* Mobile access tokens are HMAC-SHA256 over a base64url payload, signed with `COINPILOTX_SECRET_KEY`, bound to a
  device hash, and cross-checked against `mobile_security_sessions` on every request — so revocation is real
  (`POST /api/account/sessions/revoke-all`), not just expiry-based.
* A third auth tier exists: `restore_account_from_persistent_cookie()` (a "remember me" refresh cookie set by
  `set_persistent_session_cookie`, `bot.py:3079`).
* Admin auth is a **separate session key** (`admin_user_id`) from account auth (`account_user_id`). An admin is
  not automatically an account and vice versa.

### 6.1 Alias families to be aware of

Duplicate mounts are pervasive and intentional (mobile vs web vs legacy clients). The notable ones:

* `stripe_webhook` — 5 paths.
* Every reel route exists as both `/api/reels/*` and `/api/pulse/reels/*`.
* Every mobile-auth route exists as both `/api/mobile/auth/*` and `/api/pulse/mobile/auth/*`.
* Chatrooms: `/api/chat-room/*`, `/api/pulse/chatrooms/*` and `/api/pulse/messages/rooms/*` are the same handlers.
* Conversations: `/api/messages`, `/api/conversations` and `/api/pulse/messages/conversations` all bind to
  `api_pulse_message_conversations`.
* Group routes: slug form and `<int:group_id>` form, different functions, same behaviour.
* Payments: `/api/payments/*` and `/api/pulse/payments/*` overlap on entitlements, purchases, orders and
  seller orders.
* Communications 2.0: `/api/pulse/communications/v2/*` with a shorter `/api/pulse/comm/v2/*` alias for a subset.
* Seven legacy home paths collapse into `legacy_pulsesoc_home_redirect`.
* Push: `subscribe`/`register-device` and `unsubscribe`/`revoke-device`.

A rename or auth change must be applied to every alias — the handler is shared, but the decorators are not.
