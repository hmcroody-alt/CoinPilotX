# CJ catalog, variants, stock, storage, and sourcing: official-document evidence

Discovery date: 2026-09-07. Scope: public official CJ documentation only; no authenticated CJ requests, customer data, account mutations, or implementation. Endpoint/schema facts below were read from current official HTML. API responses were **not** exercised. `R` means required by the documented request table; `O` means optional. Documented examples and prose occasionally conflict; those conflicts remain visible below.

All API URLs in this file use `https://developers.cjdropshipping.com/api2.0/v1/`. Catalog/storage requests use `CJ-Access-Token`; JSON POST requests use `Content-Type: application/json`. Full endpoint URLs are provided individually to avoid confusing V2 product search with the API version prefix.

## Decisions the documents support

- Catalog discovery is supported: categories → List V2 → product details → optional dedicated variants → inventory by product. CJ's [product synchronization guide](https://developers.cjdropshipping.com/en/api/start/Products-Synchronization-Processing.html#detailed-steps) explicitly describes this sequence and inventory checking before listing.
- A universal **Add to My Product before ordering** requirement is not documented in the inspected catalog or workflow pages. The [order guide](https://developers.cjdropshipping.com/en/api/start/Orders-Synchronization-Processing.html#_3-5-comparison-with-cj-product-order-flow) says default `orderFlow=1` uses a valid CJ variant ID or CJ SKU and needs no additional connection maintenance. `orderFlow=2` can accept store identifiers but unconnected products produce invalid orders until their CJ connection is completed. These are distinct concepts: collection membership (`myProduct`), store-product connection, and order-flow selection. Account-level Store Order Flow can apply even when the request omits `orderFlow`; confirm the actual account setting before implementation. Documentation evidence supports direct CJ `vid`/SKU flow, but this discovery did not prove actual account order eligibility.
- Product-list stock is aggregate discovery data. Product totals, per-variant stock, per-country stock, physical subwarehouse stock, factory stock, and the account's private inventory are separate scopes. A country stock filter is not a shipping quote or destination-delivery guarantee.
- `verifiedWarehouse=1` means verified inventory; `2` means unverified/pending-verification inventory. The API does not turn this into a guarantee that a particular customer order has reserved stock.
- The reviews endpoint exposes supplier-catalog review data; no inspected review schema field establishes PulseSoc purchase verification, publication licensing, reviewer consent, or review provenance. API availability alone does not establish rights to republish reviews or media. Product videos explicitly expose purchase/copyright state, reinforcing that a returned URL is not a blanket reuse grant.

## Current points and frequency constraints

The [points policy](https://developers.cjdropshipping.com/en/api/api2/standard/points.html#api-endpoint-point-costs) became effective June 1, 2026 for new registrants and July 1 for earlier registrants. Every account receives 50,000 base points per UTC day; order conversion adds 100 points per USD, based on the maximum of the previous three months' transaction amounts. Current availability replenishes each minute at `daily total / 1440`, capped at the daily total. Thus 50,000/day is not a guarantee that all 50,000 points are immediately spendable. Responses expose `pointsInfo`; insufficient points return HTTP 429. Unlisted endpoints consume no points **under this published cost table**; that does not remove other access constraints.

The separate [frequency page](https://developers.cjdropshipping.com/en/api/start/limit.html#base-frequency) still documents 10 requests/second/IP, a maximum 30/second for non-login interfaces, and three users/IP. Its [level limits](https://developers.cjdropshipping.com/en/api/start/limit.html#special-frequency) are 1/second for Free or levels 0–1; 2 for Plus/level 2; 4 for Prime/level 3; 6 for Advanced/levels 4–5. It explicitly says old daily call limits are deprecated. Preserve both points budgeting and QPS throttling until CJ confirms their interaction for the account. Zero CJ transaction amount for 30 consecutive days can suspend API access; the policy describes reactivation in My CJ.

List V2 field semantics from [Product 1.2](https://developers.cjdropshipping.com/en/api/api2/api/product.html#_1-2-product-list-v2-get):

- `keyWord` searches name or SKU. `countryCode` limits products with stock in that country. `verifiedWarehouse`: omitted/0 all, 1 verified, 2 unverified. Inventory range uses `startWarehouseInventory/endWarehouseInventory`.
- `productType` filter: 4 supplier, 10 video, 11 non-video. `productFlag`: 0 trending, 1 new, 2 video, 3 slow-moving. These filter enums are not interchangeable with returned product-type codes.
- `orderBy`: 0 best match, 1 listing count, 2 sell price, 3 creation time, 4 inventory; `sort` defaults `desc` and also accepts `asc`. `timeStart/timeEnd` are milliseconds.
- Feature values: `enable_description`, `enable_category`, `enable_combine`, `enable_video`. Returned video references are IDs. Array query serialization is not illustrated comprehensively; preserve this as a contract-test item.
- Product ID is `id`; both `sku` and `spu` are documented as product SPU. Images use `bigImage`; description is feature-gated. `sellPrice` is a USD string; `nowPrice/discountPrice` and `discountPriceRate` expose discounts. Do not confuse a displayed product range with a selected variant quote.
- Inventory summary: `warehouseInventoryNum`, `totalVerifiedInventory`, `totalUnVerifiedInventory`, `verifiedWarehouse`; additional `inventoryInfo/variantInventories` are JSON strings. `myProduct` is Boolean collection membership. `deliveryCycle` is days. Old List `deliveryTime` is 24/48/72 hours to ship, not end-to-end delivery time.
- `saleStatus=3` is on sale. `authorityStatus` documents 0 private / 1 public, while the full-detail POST documents a different `authoritystatus` enum; do not share one unqualified enum across endpoint adapters.
- `hasCECertification`, customization and supplier markers are metadata, not a conclusion that PulseSoc has met all product compliance or brand/resale obligations.

The [November 19, 2025 announcement](https://developers.cjdropshipping.com/en/api/introduction.html#update-announcements) confirms subwarehouse distribution was added to inventory by product ID. Keep `areaId` (warehouse area) separate from `stockId` (subwarehouse) and query physical warehouse metadata by its documented storage identifier. Some examples contain brace-wrapped subwarehouse IDs; do not normalize or strip characters without verified API requirements.

Read values are observations, not reservations. No inspected stock query documents an atomic reserve operation, freshness SLA, or firm allocation guarantee. Suggested implementation decision for later: persist observation time and stock scope, refresh selected-variant/source warehouse stock before quotation/order creation, and handle insufficiency as a recoverable order error.

[Notification filtering](https://developers.cjdropshipping.com/en/api/api2/api/webhook.html#_3-notification-rules) applies product subscription to **both** product/variant and stock events. A successful set operation alone does not establish all-catalog coverage. Topics can auto-close when each of the previous two complete hours has <80% success (configurable); manual reactivation is then required.

[PRODUCT payload](https://developers.cjdropshipping.com/en/api/start/webhook.html#product-message-product): `messageId`, `type=PRODUCT`, `messageType=INSERT/UPDATE/DELETE`, and `params` including pid, names/description/image/category, properties, price/SKU/status, and `fields`. Product status 2 off sale / 3 on sale. [VARIANT payload](https://developers.cjdropshipping.com/en/api/start/webhook.html#inbound-message-for-variant): vid, names/image/SKU/option key/value1–3, measurements g/mm, price USD, variant status **0 off sale / 1 on sale**. Product and variant status enums differ.

[STOCK payload](https://developers.cjdropshipping.com/en/api/start/webhook.html#stock-message): example only, with `params` a map keyed by vid, each value an array of `vid/areaId/areaEn/countryCode/storageNum`. No explicit verified/factory/subwarehouse fields, observation timestamp, or event-version contract is provided there. The callback still uses `storageNum` although REST stock declares that field deprecated. Treat the event as an invalidation signal followed by authoritative REST stock retrieval until CJ validates richer payloads and snapshot/delta semantics. Do not infer REST's `totalInventoryNum` exists in callbacks.

[Signing instructions](https://developers.cjdropshipping.com/en/api/start/webhook.html#_2-signature-authentication): `sign` header is standard padded Base64 of HMAC-SHA256 over the original raw body, secret the saved string `openId` from token acquisition. No JSON reserialization. `openId` is itself signing-secret material and must be masked in logs. Receiver success must be HTTP200 within3 seconds. The inspected stock section does not document event ordering or stock-specific replay/version guarantees.

The [sourcing callback section](https://developers.cjdropshipping.com/en/api/start/webhook.html#source-product-creation-result) lists CJ product/variant/SKU/sourcing IDs, status/failure reason/date, but its type table says `ORDERSPLIT`; this appears inconsistent with a sourcing event. Confirm actual topic/type with CJ before subscribing or relying on it. The current queryList endpoint is a documented reconciliation fallback.
