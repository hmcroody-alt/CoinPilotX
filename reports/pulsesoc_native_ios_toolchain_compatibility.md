# PulseSoc Native iOS Toolchain Compatibility

Date: 2026-07-04

## Scope

This report resolves the iOS simulator QA blocker for the parallel native QA app identity:

- Native QA identity: `com.pulsesoc.nativeapp`
- Protected production identity: `com.pulsesoc.app`
- Production WebView routes: untouched

The goal was not to build a new feature. The goal was to make iOS simulator QA possible without Expo Go blocking interaction.

## Starting Problem

The previous native iOS simulator QA pass proved that the iPhone 17 Pro simulator could boot, but the native app was still on Expo SDK 51. `expo-doctor` rejected the current local Xcode:

```text
Your Expo SDK version 51 is not compatible with Xcode 26.6.0.
Required Xcode version: <=16.2.0.
```

Expo Go also blocked interactive QA with its first-run developer menu overlay. That meant the app could bundle, but Camera Studio could not be credibly simulator-tested.

## Recommendation First

Safest repo-side option: upgrade the parallel `mobile-native` app to Expo SDK 54 and run an installed native development build for `com.pulsesoc.nativeapp`.

Why:

- Local Xcode is `Xcode 26.6`.
- Only `Xcode.app` is installed under `/Applications`, so using older Xcode is an external manual setup path, not a repo-side fix.
- Expo SDK 54 officially targets React Native 0.81 and recommends Xcode 26.
- A native development build avoids Expo Go's first-run overlay and installs the correct QA bundle identifier.

Rejected as primary path:

- Installing older Xcode: safer for avoiding dependency churn, but it is machine-side manual setup and does not prepare the native app for current iOS 26/Xcode 26 QA.
- Staying on Expo Go: does not verify `com.pulsesoc.nativeapp` and still blocks interaction with Expo Go UI.
- Upgrading blindly to latest Expo: rejected. The safer bounded upgrade is SDK 54 because it is the documented Xcode 26 compatibility target and the temp-copy verification passed before repo changes.

## Risk Assessment

Risk: Medium-high.

Reasons:

- The dependency change moves from Expo SDK 51 / React Native 0.74 / React 18 to Expo SDK 54 / React Native 0.81 / React 19.
- Reanimated moves from v3 to v4 and requires `react-native-worklets`.
- Expo module APIs changed for notifications and file-system metadata calls.
- `expo-av` now emits a deprecation warning and should be migrated to `expo-audio` / `expo-video` in a later media hardening pass.

Risk controls used:

- Tested the SDK 54 dependency path in `/tmp/pulsesoc-native-upgrade-test` before modifying the repo.
- Applied only localized source compatibility changes after the temp copy passed.
- Kept generated native project output out of the commit by adding a `mobile-native/.gitignore` guard.
- Verified install, typecheck, Expo Doctor, Xcode simulator build, installed app identity, bundling, and login-screen rendering.

## Implemented Fix

Dependency upgrade:

- `expo`: `~54.0.35`
- `react-native`: `^0.81.5`
- `react`: `^19.1.0`
- `react-dom`: `^19.1.0`
- Expo modules aligned with SDK 54 through `CI=1 npx expo install --fix`
- Added `react-native-worklets` for Reanimated 4
- Added top-level `babel-preset-expo` because Metro requires it from the checked-in Babel config

Source compatibility:

- Added `shouldShowBanner` and `shouldShowList` to the notification foreground handler for SDK 54 notification behavior typing.
- Removed obsolete `{ size: true }` options from `FileSystem.getInfoAsync(...)` calls while preserving existing size fallback behavior.

Script compatibility:

- Corrected `ios:simulator` to use SDK 54's `expo run:ios --device` flow.

Generated-output safety:

- Added `mobile-native/.gitignore` entries for `/ios/`, `/android/`, and `/.expo/`.

## Remaining Limits

Now verified:

- SDK 54 dependency set is compatible enough to install, typecheck, pass Expo Doctor, build with Xcode 26.6, install on iPhone 17 Pro simulator, and render PulseSoc login through `com.pulsesoc.nativeapp`.

Still not verified:

- Authenticated simulator login/session restore.
- Camera Studio route on simulator.
- Camera permission accept/deny.
- Microphone permission accept/deny.
- Gallery fallback.
- Preview/caption/privacy/destination flow.
- Upload handoff.
- Publish destination routing.
- Physical-device camera, microphone, video capture, compression, large uploads, push, lock-screen notification behavior, and installed notification taps.

## Rollback Plan

If SDK 54 introduces unacceptable regressions:

1. Revert only this compatibility commit.
2. Return `mobile-native/package.json` and `mobile-native/package-lock.json` to the SDK 51 dependency set.
3. Revert the SDK 54 notification/file-system compatibility edits.
4. Keep production WebView untouched.
5. Use external toolchain fallback by installing/selecting Xcode `<=16.2` for SDK 51 simulator QA, or build a cloud development-client artifact on a compatible EAS image.

## Next Recommended Action

Run Camera Studio iOS simulator QA again through the installed `com.pulsesoc.nativeapp` development build.

Do not move into LiveKit calls yet. The simulator build path is now unblocked, but Camera Studio and media capture still require focused simulator and physical-device QA before higher-risk native calls.
