{# The 503 a marketplace route serves to a logged-out reader -- including Googlebot -- when it could not read the product or the catalogue. WHY THIS TEMPLATE EXISTS ------------------------ Neither of the two success frames can serve this state. `pulse_social_shell` calls `require_account()` and 302s, so routing a logged-out reader through the member frame would answer a canonical product URL with a redirect to /login -- for a crawler, the URL stops being a product at all. The public frames (`marketplace_product_public.html`, `marketplace_index_public.html`) are built from a listing payload, which is precisely what a failed read does not have. So this is the same frame the public success pages use, with the storefront's own rendered apology dropped into it. WHAT IS DELIBERATELY ABSENT --------------------------- No `schema_json`. The shell only emits the `ld+json` block when one is passed, and this page passes none on purpose: a crawler that ignores the 503 must not be handed an empty `Product`.
