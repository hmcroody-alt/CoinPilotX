{# The product page an anonymous visitor sees -- which is the same page Googlebot sees, because the branch upstream is on authentication and not on user-agent. WHY THIS TEMPLATE EXISTS AT ALL ------------------------------- `/pulse/marketplace/` already rendered a complete product page, through `pulse_social_shell`. That shell calls `require_account()` itself and 302s, so it can never serve a logged-out reader no matter what the route does: the redirect was in two places, not one. It is also the signed-in app chrome -- a left nav with Messenger, Settings and Log Out -- which is the right frame for a member and the wrong frame for someone arriving from a search result who has no account yet. So a signed-in member keeps the shell they had, and this template serves everyone else. One URL, one canonical, two frames. The alternative -- a second product path for the public version -- would split one product's ranking signal across two URLs and make the canonical tag a coin toss. WHAT IS DELIBERATELY ABSENT --------------------------- The three buyer verbs the signed-in page offers (Contact Seller, Save, Report) are not here as dead buttons. Each is a POST that needs a session, so rendering them would either fail on click or bounce to /login after the reader had already committed to an action. The sign-in link states the requirement before the click instead. No price is printed when the row's `price_label` did not parse. This is the same rule the signed-in page and the grid already follow -- no price, no pill -- and it matters more here, because this page's price is also a structured claim to a search engine. #} {% extends "_public_shell.html" %} {% from "_app_link_cta.html" import app_open_cta, app_store_badge with context %} {% block content %}
