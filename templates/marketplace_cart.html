{# The web Marketplace cart. A FRAGMENT, not a document. `pulse_social_shell()` in bot.py supplies the navigation, the signed-in header and the app CTA, and already redirects an anonymous visitor to /login, so this file renders only the cart's own markup. ## No new backend Everything here is driven by `services/marketplace_cart_routes.py`, which has answered the native app since before there was a web cart: GET /api/pulse/marketplace/cart the lines POST /api/pulse/marketplace/cart add PATCH /api/pulse/marketplace/cart/ quantity DELETE /api/pulse/marketplace/cart/ remove POST /api/pulse/marketplace/cart//confirm-price GET /api/pulse/marketplace/cart/checkout-options Its `_require_user()` resolves through `bot.api_account_user()`, which accepts the web session cookie, so the browser is already an authenticated caller. The module's own `_error()` docstring says its messages stay human "because web and admin surfaces render it directly" -- this page is the surface that docstring was anticipating. Adding a parallel `/api/web/cart` would have been two carts. ## Empty rather than clever The line list is rendered by JavaScript from the API rather than server-side, which is a deliberate choice and a narrow one: the quantity and remove controls have to re-read the cart anyway, and a server-rendered first paint that then disagreed with the first mutation would be two sources for one list. The cost is that this page needs JS, and the mitigation is that it says so rather than showing a blank panel -- see `.needsjs` below, which is visible by default and hidden by the script once it runs. ## Line states are the server's words `_line_state()` classifies every line as available, price_changed, low_stock, sold, restricted or removed, and the API returns both the snapshot price and the price now. This page prints the state rather than flattening it to "in stock", because a price that moved after the buyer added the line is the one thing they must be told before paying, and `confirm-price` exists precisely so that telling them is a step rather than a surprise. #} {# The app handoff href is injected rather than written into the JavaScript, because `services/app_links.py` owns what a PulseSoc destination's link looks like and a second copy in a script would be a second registry. It is deliberately the `/open/...` interstitial and not the canonical marker link: this button is tapped from pulsesoc.com, and iOS does not consult associated domains for a same-domain tap, so a marker link would 302 an installed member to the App Store. `open_interstitial_url` documents that in full. #}
